# Стендовая проверка на железе (ESP32-C3 Super Mini)

Тест без облака: проверяем датчики, логику и выходы по логам Serial. Нагреватель и вентилятор не нужны — их выходы заведены петлёй на отдельные входы, и прошивка сама сверяет «скомандовали → пин переключился».

## Что понадобится

- плата ESP32-C3 Super Mini + USB-C кабель;
- датчик SHT31 (модуль с подтяжками I2C);
- термистор NTC 100K + резистор `4.7 kΩ`;
- 2 перемычки для петли обратной связи.

## Распиновка

!!! warning "Сверьтесь с шелкографией своей платы"
    Номера ниже — для типового Super Mini. Если какого-то вывода (например `GPIO10`) на вашей плате нет — выберите другой свободный и переопределите в `platformio.ini` через `-DPIN_FAN=...` и т.п.

| Узел | GPIO | Куда |
|------|------|------|
| SHT31 SDA | 8 | SDA модуля |
| SHT31 SCL | 9 | SCL модуля |
| SHT31 питание | — | `3V3` и `GND` |
| Термистор (ADC) | 3 | средняя точка делителя |
| Нагреватель (выход) | 5 | перемычка на GPIO6 |
| Вентилятор (выход) | 10 | перемычка на GPIO7 |
| Readback нагревателя (вход) | 6 | перемычка с GPIO5 |
| Readback вентилятора (вход) | 7 | перемычка с GPIO10 |

!!! note "Почему термистор на GPIO3, а не GPIO2"
    GPIO2 на ESP32-C3 — strapping-пин. Делитель термистора тянет его в ноль при старте, и плата может не загрузиться. GPIO3 — обычный ADC1, без этой проблемы.

### Делитель термистора

```
3V3 ── термистор ──┬── GPIO3
                   └── 4.7kΩ ── GND
```

### Петля обратной связи (2 перемычки)

```
GPIO5  ──── GPIO6     (выход нагревателя → вход readback)
GPIO10 ──── GPIO7     (выход вентилятора → вход readback)
```

## Прошивка и запуск

Окружение `bench` в [platformio.ini](platformio.ini). Подключите плату по USB и:

```bash
pio run -e bench -t upload
pio device monitor -e bench
```

## Что показывает лог

Раз в секунду печатается строка:

```
[BENCH] t=12s air=24.8 hum=41 heaterT=25.1(raw=312) target=35 hyst=2 heating=1 | HEAT cmd=1 fb=1 OK | FAN cmd=1 fb=1 OK
```

- `air`, `hum` — реальные показания SHT31 (если `НЕ НАЙДЕН` в шапке — проверьте I2C);
- `heaterT`, `raw` — температура с термистора и сырой код АЦП;
- `target` каждые 8 с прыгает выше/ниже `air`, поэтому `heating` переключается 1↔0;
- `HEAT`/`FAN`: `cmd` — что скомандовала логика, `fb` — что реально на пине (через петлю). `OK` = совпало, `FAIL` = выход не переключился или перемычка не та.

## Критерии «прошло»

1. В шапке `SHT31: OK`, `air`/`hum` правдоподобны (комнатные).
2. `heaterT` около комнатной; при прогреве термистора пальцами — растёт.
3. Каждые 8 с `heating` меняется, и за ним `HEAT cmd`/`FAN cmd`.
4. Всегда `fb` совпадает с `cmd` (везде `OK`) — значит выходы физически переключаются.

## Доп. тест защиты нагревателя (вручную)

Когда `heating=1` (логика хочет греть), прогрейте термистор выше `80 °C` (или временно опустите `HEATER_MAX_C`). В логе `HEAT cmd` должен стать `0` несмотря на `heating=1` — сработала защита по термистору.
