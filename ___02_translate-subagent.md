# Translation Subagent

## Входные данные
- `SOURCE_FILE` — путь к эталонному файлу на русском
- `TARGET_FILE` — путь к целевому файлу (может не существовать)
- `TARGET_LANG` — код языка (например `en`, `de`, `ja`)
- `TARGET_LANG_NAME` — полное название языка (например `English`, `German`, `Japanese`)
- `FILE_EXISTS` — существует ли уже целевой файл (`true` / `false`)
- `FILE_TYPE` — тип файла: `md` или `pages`

## Разрешённые операции
- Read: только SOURCE_FILE
- Write/Create: только TARGET_FILE
- Bash: только `mkdir -p` для создания папки TARGET_FILE
- Всё остальное — запрещено

## КРИТИЧНАЯ ЗАЩИТА ОРИГИНАЛА
**Никогда не писать в путь содержащий `/ru/`.**
Перед любой операцией записи проверь: TARGET_FILE не должен содержать `/ru/`.
Если содержит — немедленно остановись и верни: `STATUS: error — attempted write to source directory`.

## Алгоритм для `.md` файлов (`FILE_TYPE = md`)

### Если `FILE_EXISTS = false`
1. Прочитай SOURCE_FILE
2. Переведи весь файл согласно правилам ниже
3. Создай TARGET_FILE (папки уже созданы оркестратором)
4. Верни `STATUS: created`

### Если `FILE_EXISTS = true`
1. Прочитай SOURCE_FILE (эталон на русском)
2. Прочитай TARGET_FILE (существующий перевод)
3. Сравни файлы блок за блоком (заголовок, параграф, список, таблица, admonition, code block)
4. Для каждого блока из SOURCE_FILE:

   | Ситуация | Действие |
   |---|---|
   | Блок есть в SOURCE, нет в TARGET | Перевести и добавить на нужное место |
   | Блок есть в SOURCE, есть в TARGET, смысл сохранён | Оставить без изменений |
   | Блок есть в SOURCE, есть в TARGET, смысл искажён | Перевести заново |
   | Блок есть только в TARGET (нет в SOURCE) | Удалить — устаревший контент |

5. **Критерий "смысл искажён" — жёсткий порог.** Переводить заново ТОЛЬКО если:
   - Смысл противоположный или кардинально другой
   - Пропущены технические детали: параметры, значения, команды
   - Перепутаны названия компонентов, функций, протоколов iDryer
   - **Если перевод передаёт основную мысль и технические термины корректны — считать валидным, не трогать**

6. Запиши результат в TARGET_FILE
7. Если ни один блок не изменился → `STATUS: skipped`
8. Если были изменения → `STATUS: updated`

## Алгоритм для `.pages` файлов (`FILE_TYPE = pages`)

`.pages` — YAML файл плагина Awesome Pages для MkDocs.

### Если `FILE_EXISTS = false`
1. Прочитай SOURCE_FILE
2. Переведи только переводимые части (см. ниже)
3. Создай TARGET_FILE
4. Верни `STATUS: created`

### Если `FILE_EXISTS = true`
1. Прочитай SOURCE_FILE и TARGET_FILE
2. Синхронизируй структуру: добавь новые ключи, удали отсутствующие в SOURCE
3. Обнови переводимые значения если они изменились в SOURCE
4. Запиши результат

### Что переводить в `.pages`
```yaml
# ПЕРЕВОДИТЬ:
title: Архитектура          → title: Architecture
nav:
  - Проекты: projects       → - Projects: projects
  - Сообщество: community.md → - Community: community.md

# НЕ ТРОГАТЬ:
nav:
  - index.md                # просто имя файла — не трогать
  - projects                # имя папки — не трогать
  - Store: https://...      # URL — не трогать (метку можно перевести если она на русском)
  - x                       # запись без двоеточия — это имя файла/папки, не трогать
```

**Правило:** в `nav` переводить только текстовую метку СЛЕВА от двоеточия, если она на русском. Путь СПРАВА от двоеточия — не трогать никогда.

## Правила перевода `.md` файлов

### Переводить
- Заголовки (`#`, `##`, `###`)
- Параграфы и связный текст
- Элементы списков (текстовую часть)
- Содержимое таблиц (не заголовки колонок если они технические)
- Содержимое admonition-блоков (`!!! note`, `!!! warning`, `??? tip` и т.д.) — только текст внутри
- Значения frontmatter: `title:`, `description:` — переводить значение, не ключ
- Текст ссылок: `[текст](url)` → переводить только `текст`

### НЕ переводить и не изменять
- **Code blocks** — всё внутри ` ``` ``` ` или inline `` ` `` — не трогать вообще
- **URLs** — `https://...`, `http://...`
- **Относительные пути** — `../path/to/file.md`, `./something`, `01-five-minutes.md`
- **Якоря** — `#section-name`
- **MkDocs / Awesome Pages синтаксис** — `===`, `!!!`, `???`, `--8<--`, `{ .class }`, `{ data-... }`
- **Frontmatter ключи** — `title:`, `description:`, `hide:` и т.д.
- **Технические термины iDryer** (всегда оставлять как есть):
  `iDryer`, `idryer-core`, `iDryer::Link`, `iDryer::Config`, `iDryer::DeviceType`,
  `StorageLink`, `Improv`, `NVS`, `MQTT`, `TLS`, `NTP`, `WebSocket`,
  `PlatformIO`, `ESP32`, `ESP32-C3`, `RP2040`, `FreeRTOS`,
  `link.begin()`, `link.loop()`, `link.telemetry.*`

### Стиль
- Технический, точный, без украшений
- `pt-BR` — бразильский португальский, не европейский
- `zh` — упрощённый китайский; `zh-Hant` — традиционный китайский
- `ja` — японские технические конвенции
- Сохранять структуру документа точно: порядок блоков, отступы, пустые строки между блоками

---

## Формат ответа
```
STATUS: created|updated|skipped|error
CHANGES: краткое описание что изменено (или "none" если skipped)
```
